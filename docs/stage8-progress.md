## 8.1 — результаты

Добавлена версия проверки полноты 1.0.0 для новых сессий и prompt 1.2.0. Важные вопросы задаются независимо от READY-ответа модели, но подавляются при наличии конкретного ответа в анкете/описании. Лимит — пять уникальных вопросов, обязательные имеют приоритет. Ответы-заглушки отклоняются без перезаписи сессии. Генерация повторно проверяет полноту в API и worker. История вопросов передаётся при генерации, чтобы значения вариантов не теряли смысл. Конкурирующие ответы сохраняются условным обновлением по ревизии; проигравшая вкладка получает 409.

Проверены модульные тесты API, 56 HTTP-тестов, 48 Web-тестов, прежние 19 PostgreSQL-сценариев и отдельная новая гонка двух вкладок. Браузерный сценарий ремонта ванной прошёл: три обязательных уточнения, адрес «потом» отклонён, остальные ответы сохранены, затем READY. Снимки просмотрены на 320/390/1440 px; визуальный язык Jeton сохранён. Старые завершённые генерации и подписанные договоры не переоцениваются и не меняются.

## 8.2 — результаты

Пять сценариев API + PostgreSQL прошли для работ, услуг, аренды, купли-продажи и займа. Каждый проверяет неполную/полную анкету, пустые и некорректные ответы, 1001 символ, неизвестный ключ, чужую сессию, гонку двух ответов, запрет преждевременной генерации, повторную генерацию, неверную версию шаблона, отрицательную сумму и неправильные/прошлые даты. Повторный прогон матрицы: 5/5.

Настоящий YandexGPT вызван на синтетических данных для всех пяти шаблонов без записи пользователей/сделок в рабочую БД. Неполные примеры дали 3/3/5/3/3 обязательных вопроса; после ответов — готовность; те же условия в свободном описании — готовность без повторов. Результаты генерации прочитаны полностью.

В первом реальном ответе купли-продажи отсутствовали цена, дата передачи и способ оплаты; у займа терялась единица «% годовых». Исправлено: сервер добавляет раздел «Условия сделки» из точных значений с названиями/единицами опубликованной анкеты и текстами уточнений. Неопределённое место/оплата заменяются уточнённым значением. Повторный реальный прогон содержит исходные суммы, даты, идентификаторы, проценты и ответы во всех пяти договорах. Смысловая корректность любого произвольного текста ИИ не гарантируется этим контролем; остаётся юридическая приёмка клиентом.

Также нормализуются Markdown, пустая метка `typeSectionTitle` и собственная нумерация модели перед единым рендерингом документа. Это не меняет исходные условия и не переписывает подписанные версии. Добавлены проверки передачи всех условий worker-у, пропуска повторного задания, retry, точного раздела и оформления текста. Внешние сервисы в обычном browser-наборе заменены; ручной платный прогон вынесен в `scripts/test-live-ai.cjs` с явным флагом запуска.
