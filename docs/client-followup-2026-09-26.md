# Доработки сделки, реквизитов и подписания — 26.09.2026

## Поведение

- Вход в профиль из сделки раскрывает и прокручивает паспортные данные. Ручной ввод в модальном окне также открывает паспортный раздел; импорт сначала показывает данные для проверки.
- Приглашение остаётся доступным во время заполнения, в том числе на экране ожидания реквизитов. Обе стороны могут заполнять данные параллельно.
- Генерация требует присоединения двух участников и заполненных паспортных реквизитов обоих профилей. Проверка действует перед очередью, в worker и при сохранении проекта/начале согласования. Анкета и уточнения доступны заранее.
- Полные ФИО добавляются сервером после ответа ИИ; данные профилей не передаются в запрос генерации. Проект привязан к конкретной сделке. Изменение ФИО до согласования требует новой редакции. Уже подписанные версии не переписываются.
- В черновике второй стороны доступны три способа ввода реквизитов и сообщение об ожидании. Несформированный договор не открывается.
- Публичное приглашение: «Проверьте условия вместе». Раздел участников: «Стороны и приглашения». Убран повторный текст о роли.
- Прямая загрузка фото/файлов в форме вместо вложенного экрана документов. Общие файлы показаны одним списком; обязательные требования и приватность личных документов сохранены. Шапка документов закреплена.
- Новые редакции выделены жёлтым; серый черновик и зелёная завершённая сделка сохранены.
- Смена года/месяца в календаре сохраняет выбранный день; для короткого месяца день ограничивается его последним днём. Пустая дата не заполняется одной навигацией.
- Диалоги согласия и OTP компактные. Не удалены юридические условия, явное согласие и доступ к отпечатку. На очень малых высотах/при увеличенном шрифте остаётся безопасная прокрутка вместо обрезки.
- PDF и ZIP новых завершённых сделок ставятся в транзакционную очередь отправки обоим участникам MAX. Учитывается согласие на уведомления. Приватные сканы в пакет не включаются. Старые завершённые сделки не рассылать автоматически.

## Проверки

- `npm run test`: 569 API + 191 web.
- `npm run test:e2e --workspace @max-contract/api`: 72.
- `npx playwright test --config playwright.layout.config.ts`: 22 изолированных браузерных сценария, включая обе стороны до генерации, загрузку, календарь, закреплённую шапку и согласие/OTP на 320×568, 390×650, 430×844.
- `npm run lint`, `npm run typecheck`, production-сборка web.
- API/браузерные проверки используют искусственные данные и имитацию внешних сообщений. Реальная доставка в личные сообщения MAX и поведение внутри мобильного webview требуют приёмки двумя тестовыми аккаунтами. Старый полный browser lifecycle с приглашением после генерации больше не соответствует новому порядку; изолированный прогон не является его полным запуском.

## Приёмка на двух тестовых аккаунтах

1. Начать черновик, пригласить вторую сторону до завершения анкеты.
2. Заполнить только один профиль: генерация недоступна. Заполнить второй: кнопка становится доступной после обновления статуса.
3. Подготовить договор, проверить ФИО, приложения и согласовать одну редакцию обеими сторонами.
4. Подписать обоими аккаунтами. Проверить PDF и ZIP в MAX и скачивание из приложения. Проверить согласие на уведомления, если сообщения не приходят.
