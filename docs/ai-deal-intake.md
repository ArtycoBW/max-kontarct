# Создание договора по описанию

На первом шаге создания сделки доступны два пути: описание задачи для ИИ и ручной выбор из каталога. Обычный поиск по названиям явно отделён от ИИ; при отсутствии совпадений введённый текст можно перенести в поле описания.

## Пользовательский сценарий

1. Ввести описание от 10 до 500 символов без личных реквизитов.
2. Нажать «Подобрать договор с ИИ».
3. Проверить предложенный тип, название, извлечённые значения и замечания.
4. Нажать «Проверить и продолжить». До этого подтверждения черновик сделки не создаётся.
5. Проверить название и исходное описание, затем исправить или дополнить предзаполненную анкету.
6. Пройти уточнения, подготовку договора и существующий процесс согласования и подписания.

При отсутствии подходящего типа применяется внутренняя анкета `individual-agreement`: предмет, обязанности каждой стороны и дополнительные условия. На её основе ИИ создаёт индивидуальный проект договора. Это не автоматическая публикация нового юридически проверенного шаблона. Персональные условия хранятся в принадлежащей пользователю сделке и AI-сессии, а не в общей библиотеке. В индивидуальный проект сервер добавляет предупреждение о необходимости проверки.

## API и безопасность

- `POST /api/v1/deal-intake` с `{ "description": "..." }` требует действующей сессии. Возвращает предложение, но ничего не публикует и не создаёт сделку.
- Запросы ограничены шестью обращениями в минуту на IP стандартным ограничителем API.
- Модель выбирает только из переданных опубликованных типов и внутренней индивидуальной анкеты. Схема ответа и поля выбранной анкеты проверяются сервером.
- Для извлечённых значений необходима цитата из описания. Текст сохраняется без новой интерпретации; суммы и абсолютные даты дополнительно сопоставляются с цитатой. Невалидные, неподтверждённые и дублирующиеся значения не предзаполняются.
- Исходное описание передаётся в уточнения и генерацию как контекст. Проверенные поля и ответы имеют приоритет. Если автор явно указал свою роль (например, исполнитель), генератор получает требование обозначить её соответствие инициатору; роли и весь текст всё равно проверяют стороны. Реквизиты сторон по-прежнему берутся из профилей.
- Сбой ИИ оставляет описание на экране, позволяет повторить запрос или выбрать тип вручную. Сохранение неподтверждённого текста при закрытии приложения до создания черновика не предусмотрено.
- Для индивидуальных приглашений публично разрешены только стандартное безопасное обозначение предмета, срок и сумма; свободное описание и обязанности не добавлены в публичный whitelist.

## Ограничения

ИИ может ошибаться в выборе типа и интерпретации задачи. Предложение требует проверки пользователем, а индивидуальные договоры — проверки применимости условий. Распознавание паспорта, голосовой ввод, геолокация и раннее приглашение этим изменением не добавляются. Существующие требования к профилю, документам и подписанию не ослабляются. Индивидуальная анкета предназначена для двух физических лиц; отдельные процессы для организаций и других неподдерживаемых сценариев не реализованы.

## Выкладка и проверка

Перед запуском нового API применить миграцию `20260908150000_individual_agreement`. Она добавляет только внутреннюю анкету и требования к документам, не меняет существующие договоры и версии. Ключ YandexGPT остаётся только на сервере.

Автоматические проверки: `deal-intake.service.spec.ts`, `deal-intake.e2e-spec.ts`, `tests/browser/deal-intake.spec.ts`, проверки передачи контекста и индивидуального проекта в тестах уточнений и генератора. Браузерные тесты используют отдельную временную базу; запуск на рабочей базе запрещён.
