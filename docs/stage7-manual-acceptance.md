# Этап 7 — проверка в MAX

Проверять новую сделку: ранее подписанные PDF и ZIP остаются неизменными. Перед проверкой полностью закрыть мини-приложение и открыть его снова на обоих аккаунтах, чтобы загрузилась новая версия интерфейса.

1. **Первый аккаунт → Создать.** Выбрать тип, заполнить описание и анкету, подготовить договор. Не должно быть английских служебных сообщений и обещаний будущих функций. Если анкета уже содержит ответ, повторный вопрос не нужен. Перед сохранением прочитать условия.
2. **Приглашение → второй аккаунт.** Открыть ссылку, прочитать условия, продолжить оформление. Отказ от необязательных статусных уведомлений не должен мешать работе. Заполнить профиль.
3. **Документы сделки.** Загрузить обязательные документы с обоих аккаунтов. Документ личности первого участника не должен быть виден второму. Неверный формат и файл больше 20 МБ должны давать понятную ошибку; файл допустимого размера больше 12 МБ должен загружаться.
4. **Администратор → Проверка файлов.** Проверить документы. Вставить длинный комментарий без пробелов: он переносится и прокручивается внутри карточки; карточки одинаковой высоты, кнопки остаются доступны. На телефоне окно проверки не выходит за ширину экрана. До принятия всех обязательных документов согласование недоступно.
5. **Оба аккаунта → Сделка.** Согласовать одну версию по одному разу. На первом аккаунте оставить экран открытым: после согласования вторым статус должен обновиться автоматически, обычно в течение нескольких секунд. Изменение условий требует нового согласования, повторное нажатие для неизменной версии не требуется.
6. **Подписание.** Принять соглашение о ПЭП, запросить код, подписать с каждого аккаунта. На стенде код приходит от бота MAX; рабочий SMSC подключается после получения клиентских реквизитов. Ошибочный код не подписывает договор. После второй подписи оба открытых экрана переходят к готовым файлам.
7. **Скачать PDF и пакет материалов.** PDF содержит договор и сведения о подписях. QR открывает отдельную страницу проверки документа, а не чат бота. Публичная страница не показывает телефоны, ФИО и личные документы. Новый ZIP содержит понятное описание состава без оговорки о принятии судом; личные документы сторон не включены в общий архив.

На шагах 3–7 дополнительно проверить нижний отступ, отсутствие горизонтальной прокрутки и читаемость текста в MAX на телефоне и компьютере. Для сообщения о проблеме достаточно названия сделки, шага, времени и снимка экрана — коды подписи и личные документы присылать не нужно.

Финальная пользовательская приёмка ещё не заменяет подключение клиентских провайдеров и утверждение юридических текстов. Их отдельный список ведётся в `CLIENT_HANDOFF_REMAINING.md`.
