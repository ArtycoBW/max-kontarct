Итого **399 тестов**, повторные прогоны не суммируются. После последнего изменения порядка полей дополнительно повторены модульные проверки API и typecheck. Порядок анкет берётся из `x-fieldOrder`, а не из алфавитного порядка ключей PostgreSQL JSONB.

Браузерный набор работает с настоящими API и PostgreSQL, но с изолированными сессиями и тестовыми MAX/ИИ/SMS/S3. В отдельном реальном прогоне использовался серверный YandexGPT и синтетические условия: без записи пользователей, сделок или подписей в рабочую базу. Открытые Brave/Яндекс с реальными аккаунтами не использовались: Computer Use остановил взаимодействие по проверке URL; владелец разрешил продолжить через автотесты. Не считать это ручной приёмкой в целевых браузерах.

## Что покрыто

- Все пять шаблонов: неполная/полная анкета, обязательные уточнения, ответы-заглушки, неверный тип/размер/ключ, сохранение ответов, отсутствие повторов, доступ чужого аккаунта, конкурирующие ответы, запрет преждевременной генерации, повторная генерация, версия шаблона, суммы и даты.
- Полный цикл с двумя участниками и администратором: приглашение, onboarding, профили, личные и общие файлы, ручная проверка, запрет повторного принятия, согласование, две подписи, обновление первой открытой вкладки, скачивание и публичная проверка.
- Отрицательные сценарии авторизации, IDOR, rate limit приглашений, HTML в комментарии, неподходящий MIME/сигнатура файла, размер, OTP, конфликт версии и неизменяемость подписанных снимков.
- SMSC: 12 проверок; DaData: 14 проверок. Таймауты, отказ провайдера, неверные типы и пустые/повреждённые ответы не превращаются в успех или сырую ошибку.
- Проверка конфигурации не выводит секреты. S3-probe сначала подтверждает существование объекта с авторизацией, затем требует запрета чтения без неё. Публичный 200/206, редиректы и 500 не считаются приватным хранилищем.

## Реальный YandexGPT и исправления

Неполные примеры работ/услуг/аренды/продажи/займа дали соответственно 3/3/5/3/3 обязательных вопроса. После ответов все готовы к генерации. Полные те же условия в описании — готовность без повторного опроса. Все ответы и готовые тексты прочитаны; повторный реальный прогон после доработки успешен.

В первом ответе купли-продажи модель пропустила цену, дату и способ оплаты. Сервер теперь сохраняет точные условия отдельным разделом с названиями/единицами из опубликованной анкеты и текстами уточнений. Сохраняются также `Нет`, нулевая допустимая величина и `% годовых`. При отсутствии названия поля/вопроса генерация не теряет ответ молча.

Убраны замеченные Markdown и пустые служебные строки `typeSectionTitle`; собственная нумерация модели не дублирует нумерацию PDF. Регрессия первого полного прогона (очистка удаляла единственный пункт, равный заголовку) исправлена и покрыта тестом; полный браузерный набор после исправления прошёл.

Контроль присутствия условий не является универсальной смысловой проверкой ИИ. Модель может добавлять типовые договорные положения; например, в тесте продажи встретились заверения продавца о собственности/обременениях. Их применимость и все роли/формулировки необходимо утвердить с юристом клиента. Для нового пользовательского шаблона отдельно нужны правила полноты. Проверка существования адреса без DaData не выполняется.

Его тестовый текст не выдаётся за результат настоящей модели.

Каждый файл браузерного ZIP сверён с `manifest.sha256.json` по размеру и SHA-256; личные документы исключены. QR/URL открывает публичную страницу проверки, которая показывает хеш PDF и не раскрывает участников.
